# larsal-ffi: what Swift can call

Every function, object and type that `larsal-ffi` exports to Swift through UniFFI (proc-macros, `#[uniffi::export]`). The Swift names come from `scripts/build-core.sh`: the bindings are the module `LarsalCore`, the C layer under them is `LarsalFFI`. Nothing else crosses the boundary. A new export is added here in the same change.

Rule (architecture, `larsal-ffi` Must; AGENTS.md rule 4 as LD-220 reads it): no export returns a secret except the crossings LD-220 names, each started by the user or drawn on screen by design: the Show value the user asked for, as a `String`; the live one-time codes of the entries in view (`codes`, `totp`, `draft_code`); the setup secret in the editor's one-time password sheet (`totp_setup`); the QR matrix the user asked for (`totp_qr`, `qr_show_field`, `qr_show_draft`, `qr_show_wifi`); the generator's value (`generate`); the wizard's and vault settings' `password` and `repeat`, and the wizard's `generate`, while that sheet is open. Each export's doc line and its Secret column name its class. Copy is a Rust call and its value never reaches Swift. Errors are typed and hold no secret (AT-E03).

## Views, Show and Copy (E5-S2, E5-S4, `views.rs`)

Entry and group ids are 32 hex digits (ASCII only; a sign such as `+` is refused). Every id is looked up only in the vault the call names: an id of another vault, or any malformed id, gives `UnknownEntry` or `UnknownGroup` (AT-E03). Text inputs over 64 KiB give `TooLong`. Calls on a locked vault give `Locked`.

## The editor and the window's vault changes (E5-S5, `edit.rs`)

The editor works on a draft held in Rust, one per unlocked vault, dropped on lock; nothing changes in the vault until `commit_edit`. Every call below takes the vault id first; the draft calls answer `Refused("The editor is not open.")` without a draft. Text over 64 KiB gives `TooLong`. A vault change counts one unsaved change and drops the touched entry's ratings so the Health Check runs again (LD-139). `save` is slow (the KDF): call it off the main thread.

## Shared groups (E11-S3, `share.rs`)

INT-08 over larsal-share. The share password never leaves Rust and is in no answer (INT-08.39, AT-C06). After a pass with news Rust calls `session_changed`. A good save of the vault exports (INT-08.17); the command line tool runs no share (INT-08.40).
