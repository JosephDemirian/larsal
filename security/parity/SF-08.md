## G4 interop run with the reference command line tool (installed 2.7.11)

`REF_CLI=<reference CLI> scripts/interop.sh <cases file>`: Larsal opens each vault and saves a version 4 copy with `larsal_format::save`; the reference exports the original and the copy, and `scripts/testdata/interop_compare.py` compares them field by field. The comparison covers every string value and its protection flag, so a protected value that Larsal encrypted wrongly, or a flag it lost, would fail.

| Cases | Result |
|---|---|
| The 12 testdata vaults (password, every key file kind, password and key file, rich 3.1 and 4.1, 10,000 entries) | 12 equal; 10 of 10 attachments byte-equal |
| 18 reference test vaults: versions 2.0, 2.4 (four key file kinds), 3.0, 3.1 and 4.0, the browser and new-vault samples, the non-ASCII password, the protected-strings sample, the key-file-protected pair, the XML 2.0 key file vault, the four recycle bin samples | 18 equal; 4 of 4 attachments byte-equal |
| Done separately, through the same comparison: the empty-password sample, and the hardware-key test vault (software answer) | both equal |

Larsal writes the ChaCha20 field stream (stream id 3) with a fresh 64-byte key on every save (`t09_02_fmt_09_4_inner_header_on_write`; 60 independently decrypted resaves in [SF-07](SF-07.md)). Negative controls: copies changed by the reference (a password edit, a replaced attachment, a moved entry) and a copy that does not open all fail the comparison.
