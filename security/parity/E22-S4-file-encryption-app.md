The Mac app gains Encrypt File… and Decrypt File… in the File menu and a drop target in one sheet. Encrypt makes a new passphrase of ten built-in words, saves it as a protected entry in the open vault before any output exists, and encrypts the file to it; or takes a typed passphrase, or public recipients. Decrypt opens a file from Larsal or from another tool of the same profile with a passphrase, a vault entry or a key file. Every secret stays in Rust; Swift sees only the one value the user asked to Show. The work runs in larsal-ffi's file job over E22-S3's larsal-files, with progress, Cancel, lock and quit. The output is written in a private staging folder in the chosen folder and committed by a rename that never replaces (F-340).

## Rule 4 and rule 3, on the delta

- **What crosses to Swift.** Typed text goes from Swift to Rust on each change (`FileTyped` slots, `SecretString`); Swift keeps only whether a field is empty. The generated passphrase crosses only by Show, the one allowed value, into Larsal's no-copy field. Questions cross as numbers; progress carries a step, counts, finished and an end id. No error text carries a secret (`fil01_t19_the_bridge_gives_back_no_secret_and_uses_capture_only`).
- **Saving.** The generated passphrase is saved as a protected entry and confirmed on disk before any output exists (FIL-02.5); a typed one only when Save in vault is on, and always as a protected field.
- **Wiping.** Typed slots are wiped at a start, a Cancel, a lock, a quit and when a field is emptied; the shown value is dropped on leaving Encrypt.
- **Readable bytes on disk.** Decrypted bytes go only through `save_new` into the 0700 staging folder, then by the no-replace rename to the user's chosen name; a cancel, lock or quit empties and removes them first; the decrypt scratch holds ciphertext only, in `file-scratch` (0700) under Larsal's settings folder.
- **Rule 3.** No new outside crate: the Cargo changes add only larsal-files to the workspace and to larsal-ffi (and its `test-volume` feature to larsal-ffi's dev-dependencies, never in a product build).
