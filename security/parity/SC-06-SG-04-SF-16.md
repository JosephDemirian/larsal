## The patched crate (LD-136, LD-140)

vendor/zxcvbn diffed against the untouched 3.1.1 from the crate registry. Source changes: (1) f64 guesses (lib.rs, scoring.rs, time_estimates.rs, matching/mod.rs, matching/patterns.rs); (2) ordered maps (`Optimal`, the dictionary list, the keyboard list, the l33t tables); (3) the wasm code and its 3 `unsafe` blocks gone with `#![forbid(unsafe_code)]`; (4) one product-name entry removed from the password list (position 7,118 of 30,000; the other five lists are unchanged); (5) `matching::omnimatch` and `estimate_guesses` made public (only `pub`, a re-export in lib.rs and comments). adjacency_graphs.rs, feedback.rs, serialization_utils.rs, char_indexing.rs and LICENSE are byte-identical. lib.rs's header lists the five changes and what was left out of the copy (F-050). Upstream saturates guesses at the 64-bit maximum and reads only the first 100 characters.

## Health Check, statistics and expiry against the reference

The reference command line tool's `db-info` prints the statistics, and its weak count runs the Health Check score, so both were compared black-box on demo vaults built with the reference CLI: FEA-07's V3, V4, V7, a recycle-bin-off copy of V3, and a vault with a reference password, an excluded reused pair and two expiring entries. Re-run on the LD-140 code: every row equal (groups, entries, expired, unique, non-unique, maximum reuse, short, weak, excluded, average) in UTC, UTC+14 and UTC−8, except the weak count where D-05-4 differs on purpose: an entry expiring 2026-11-26 10:00 UTC is weak in the reference at UTC+14 (local today against the UTC date: 30 days) and not in Larsal (local dates: 31); one expiring 2026-11-26 05:00 UTC is weak in Larsal at UTC−8 (30 days) and not in the reference (31).
Read in the reference source for the parts 2.7.11 lacks: passkey entries are those with a field name starting with the passkey prefix, and TOTP entries are those whose stored settings parse, in the same order of fields as Larsal.

## Memory (LD-140 path)
