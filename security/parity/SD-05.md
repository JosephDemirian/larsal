## Side by side with the reference command line tool (installed 2.7.11)

Start: the rich demo content (fixed 2024 times) without a recycle bin, imported by the reference. Each change was made once by the reference CLI and once by App (app-core, then `app_format::save`) on the same file, and the reference exported both results.

| Step | Reference | App | Exports compared field by field |
|---|---|---|---|
| 1. Delete an entry | `rm` | `delete_entries` | equal: bin made on first use (name, icon 43, search and Auto-Type off), entry in the bin with its previous parent and its 3 history items, no deleted-object record |
| 2. Delete it again from the bin | `rm` | `delete_entries` | equal: gone for good, one record |
| 3. Delete a group with a child group and two entries | `rmdir` | `delete_group` | equal: the group moves into the bin, its own times move, its old parent's do not |
| 4. Edit a password | `edit -p` | `edit_entry` | equal, history item included |
| 5. Delete the bin itself | `rmdir` | `delete_group` | equal: 5 records in the same order (entries, child groups, then the group, FMT-15.7); the last one is each side's own random bin id |
| Cross: delete from the other tool's bin | App on the reference's bin; the reference on App's bin | — | equal to the same-tool result |

The one difference, on purpose (LD-102, D-02-1): the reference moves a group's times when an entry leaves it (seen: removing an entry two levels down changed only that group's times; removing one from the root changed the root's). App moves a group's times only for the group's own changes.

App only, so no reference comparison: restore of an entry or a group (the reference's command line has no restore; App restores a group, L04-3, and sends an entry whose previous parent is gone or in the bin to the root, L04-2: `mod_04_10_a_previous_parent_in_the_bin_sends_to_the_root`, `mod_04_11_a_parent_inside_the_group_sends_to_the_root`). App restored a group from the reference's bin, and the reference opened the result.
