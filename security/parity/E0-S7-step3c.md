## 2. The replacements

- **R9 clap (app-cli `args.rs`).** One pass over the words: a value option takes the next word whatever it looks like (`-u -h` is the user name `-h`), `--name=value`, `-xvalue` and `-x=value`, combined short flags, `--` ends the options, a single `-` is an argument, the hidden reference spellings as aliases (D-INT10-1), `-h` or `--help` outside a value is App's own help at once (INT-10.3). The first problem found is reported, in the order the old parser reported them: an unknown option, a value given to a flag or to `--help`, or `-h`, as each comes, and an extra argument where it comes; then a value option at the end with no value, a missing argument, a password given to estimate (D-INT10-4), a bad `--hw-key` value. An unknown option that also stands after a `--` reads as an extra argument, as the old error mapping did. `Parsed` holds the same `given` list as before: in help order, a flag once, a value option's last value, every value of `show -a`. The INT-10.2 and INT-10.3 unit tests, the 116 int10 tests and the M10-02 and M10-92 texts are unchanged.
- **R10 ico (app-core `icons.rs`).** The format checks of `check` and `header_size` are unchanged. `decode_ico`: at most 256 images (`MAX_ICO_IMAGES`; the format allows 65,535; the old crate had no limit), each directory entry inside the file with a zero reserved byte and its data inside the file, all data together no larger than the file (App's earlier check). Each image's size comes from its own header (a PNG of 8 bits per channel, read by `png`, or a BMP's 40-byte header: width at least 1, the height field even and its half at least 1), else the directory's bytes (0 is 256), as the old crate set it. The largest image (the last of equals, as `max_by_key` chose) must be within the pixel limit; a PNG then goes through `check` and `decode_png` as before, a BMP through `decode_bmp`: the full colour table for 1, 4 and 8 bits (F-043: a palette image whose "colours used" is set and smaller than its depth allows is refused, as since LD-116), the colour rows from the bottom up, each padded to 4 bytes, 16 bits as 5 bits per channel scaled `(c × 255 + 15) / 31`, 24 bits BGR, 32 bits BGRA with no mask, then for every depth but 32 the 1-bit mask (set is transparent); compression is not read, as the crate did not read it. Every read is a checked slice: data that ends early is refused, and the reader never reads or writes past its input. It holds slices of the input, where the crate copied every image. **The test encoder** (`tests/common/ico.rs`) writes the bytes the crate wrote, so the tests and the fuzz seeds keep their files (section 4).
- **R12 serde_json and serde (app-model `json.rs`).** RFC 8259, strict: one value with only white space around it, UTF-8, no comments, trailing commas, raw control characters or lone surrogates, no number too large for an `f64`. Input over 16 MiB (`MAX_INPUT`) is refused before it is read; nesting deeper than 127 levels (`MAX_DEPTH`, the old crate's limit: 128 refused) is refused before it is built, which bounds the recursion. Objects are a `BTreeMap` (members in key order, as the old crate's default map), a repeated key keeps its last value, or is refused by `from_slice_unique` (the instance line: serde's derive refused a repeated field). A number keeps its text: `as_i64` and `as_u64` take a whole number written without a fraction or an exponent, as the old crate (`-0`, `1.0` and `1e2` are not whole numbers there either). The writer is the compact form (`to_string`, `Display`) and the pretty form with two spaces (`to_string_pretty`), escapes as the old crate (`\"`, `\\`, `\n`, `\r`, `\t`, `\b`, `\f`, other control characters `\u00xx` in lower case, everything else as is). The API is the part of the old one App called (`Value`, `Map`, `as_*`, `get`, `["key"]`, `From`, a `json!` for objects), so the callers changed only their paths. Not for secrets: the import of other managers' files keeps its own reader (app-core `import/json.rs`, App's own code since E4-S13, which wipes its strings, FEA-08.66); it never used serde_json and is unchanged, and its tests pass (fea08 82). The instance line is read by `Wire::read` (an object of `v`, `cmd` and `paths`, no other member, none twice) and written by `Wire::line` in the old member order, so the line has the bytes serde wrote.
