## Independent checks (Verify, scratch copy)

- AT-I01: a separate program saved a 4 MiB demo vault again and again (`app_format::save` and `storage::save` with a backup, a build without the test hook); it was killed with SIGKILL at a random moment 400 times. Every time the vault was a whole old or new version, App and the reference command line tool both opened it and showed the same version, and the backup opened. 53 kills left a temp file, which APP-05.17 keeps.
- AT-I02: on a 12 MB disk image with 1 MiB free, the save failed with `StorageFull`; the vault's bytes were unchanged (same SHA-256), both apps opened it, no temp file and no backup was left.
- AT-I03: a vault in a read-only folder: permission error, old file intact, nothing left behind.
- AT-I04: the Checker's probes re-run on the current code: a symbolic or hard link planted at the backup name is replaced, the linked file untouched; a temp file swapped for a link during the write is caught and the save fails, the linked file and the vault untouched; a change on disk between the check and the rename is caught (changed on disk) and the other writer's version kept; a dangling link at the vault path gets a new file at the path (APP-05.9), and the direct method refuses it; a 249-character vault name saves; a 0400 or 0444 vault is never written. The rename window F-047 was accepted until E6; it closed in E13-S6 part b (re-tested 2026-10-30, E13-S6b-fixes.md).
- AT-I06: a new vault 0600; a re-saved 0644 vault keeps 0644; its backup 0600 (App goes further).
- SD-03, merge: the Checker's merge probes re-run: a share import stays inside the shared group (LD-130), a KDF family change is a Conflict (LD-132), 2,000 random move cases lose nothing; 100,000 objects per shape merge in at most 0.195 s in release. The reference command line tool's `merge` and App's merge, both ways on demo vaults edited differently on each side (edits, moves, deletions into the bin, new entries, history): every entry has the same group, fields, history and attachments; the only difference is the second, empty recycle bin the reference adds from the source, where App maps the source's bin to the target's (MOD-11.16).

Timings were taken with up to 11 fuzz runs going on this Mac.
